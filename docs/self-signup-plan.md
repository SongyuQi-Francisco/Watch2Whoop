# 自助注册 + 内测激活码（方案，暂不实现）

> 状态：方案（2026-10-20）。只定需求和设计，实现以后另开 PR。

## 为什么

现在每个账号都要部署者在服务器上开（`onboard.py` / 管理员脚本），再把个人激活链接发给本人。人一多，管理员就成了瓶颈。

目标：**用户自己注册**（Email 或 Apple ID），内测阶段**凭激活码开通**；管理员只需要**批量生成激活码**往外发。

## 用户流程

1. **注册 / 登录**：app 首屏「通过 Apple 登录」或「用邮箱登录」（邮箱收 6 位验证码，不设密码）。今天页（网页）同样两种方式。
2. **输入激活码**：账号刚建好是「待开通」状态，只显示一页「输入激活码」，不读、不存任何健康数据。
3. **开通**：激活码有效 → 服务器自动准备好这个人的同步账号（Open Wearables）和训练 / 饮食记录账号（SparkyFitness）→ 进入同意书 → 个人资料 → 授权健康 → 正常使用。
4. 以后换手机：直接用同一个 Apple ID / 邮箱登录，不需要激活码，也不需要管理员。

激活码只在开通时用一次，绑定到账号以后就没用了；以后公开发布时，可以把这一步关掉（不再需要激活码）。

## 管理员

- 批量生成：`body-engine invite-code batch --count 50 --label 小红书-1020 [--days 30] [--max-uses 1]` → 打印 / 导出 CSV（明文只出现这一次，库里只存 sha256）。
- 查看：每批用了多少、谁用的、什么时候；单个或整批停用。
- 以后在今天页「我」里给部署者加一个「激活码」管理页（只有 owner 能看）。

## 数据和接口（草案）

| 表 | 作用 |
|---|---|
| `user_identities` | 登录身份：`provider`（apple / email）、`subject`（Apple 的 sub / 规范化后的邮箱）、`email`、`verified_at`；一个用户可以绑多个 |
| `invite_batches` | 一批激活码：标签、创建人、有效期、每码可用次数 |
| `invite_codes` | 激活码：`code_sha256`、所属批次、`uses` / `max_uses`、`expires_at`、`revoked_at` |
| `invite_redemptions` | 谁在什么时候用了哪个码 |
| `users.status` | `pending`（已注册未开通）/ `active` / `disabled` |

接口：`POST /v1/auth/email/start`（发验证码）、`/v1/auth/email/verify`、`/v1/auth/apple`（校验 Apple identity token）→ 都返回会话；`POST /v1/account/redeem-invite`；`DELETE /v1/account`（自助删除账号）。`pending` 的账号只能调这几个接口。

开通时做的事 = 现在 `onboard.py add` 里的步骤，挪进 Body Engine 的一个幂等任务：建 OW 用户（已有开发者 JWT 签名，见 `web/activation.py`）、建 SparkyFitness 用户和读写 / 只读 key、初始化日记项目。失败可以重试，不会重复建。

## 要注意的

- **Apple 审核**：能在 app 里注册账号，就必须能在 app 里**删除账号**（App Store 审核指南 5.1.1(v)）；用了第三方登录就要同时提供「通过 Apple 登录」（4.8）。
- **发邮件**：需要一个发信服务（SMTP 或邮件 API），验证码 10 分钟有效、每个邮箱 / IP 限频。
- **防滥用**：注册和兑换都走现有的登录失败限流；`pending` 账号 7 天不开通自动删除。
- **成本**：每个新开通的人都会用到托底 AI 额度（每月 ¥3）和服务器内存；开通前检查总人数上限和托底 AI 余额。
- **隐私**：同意书之前不处理健康数据（和现在一样）；邮箱只用来登录。
- **和现有方式的关系**：管理员开户 + 个人激活链接继续保留（给不方便自己注册的家人）；已有账号以后可以在「我」里绑定 Apple ID / 邮箱，改成自己登录。
- **app 要重新打包**：首屏换成登录 + 激活码，需要新的 TestFlight 版本。

## 分阶段

1. 后端：身份表、邮箱验证码登录、激活码批次和兑换、自动开通任务、自助删除账号。
2. app 和今天页：登录页、激活码页、「我 → 删除账号」。
3. 通过 Apple 登录（app 原生 + 网页）。
4. 管理页：批量生成 / 停用 / 统计。
5. 公开发布时：激活码改成可选（开关）。
