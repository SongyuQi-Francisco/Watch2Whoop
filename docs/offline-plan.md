# 离线使用（今天页 + iOS app）

灰度开关 `offline_mode`（默认关，`rollout/registry.py`）；issue #77 一并处理。代码：`body_engine/src/body_engine/web/static/offline.js`、`app.js`（`api()`、横幅、队列弹层）、`water.js`、`training-day.js`，后端 `body_engine/src/body_engine/offline/`。测试 `tests/test_offline.py`。

## 1. 离线时能看 / 能做 / 不能做

| | 内容 |
|---|---|
| **能看** | 最近一次打开过的今天页、趋势、记录（日记、训练、饮食）、我。用本机缓存的数据显示，顶部横幅「离线 · 数据更新于 hh:mm」（不是今天的显示日期 + 时间）。没缓存过的内容显示「离线，连上网络后重试」+「重试」，不再显示「没有数据」（#77） |
| **能做** | 喝水（+250 / +500）、训练逐组（填组、打勾、提交）、体重（记录 → 日记 →「体重」，开关打开后才有这个入口）。先存进本机队列，联网后按顺序自动提交；横幅显示「N 条待同步」，点开能看每一条 |
| **不能做** | Jarvis / AI 对话、朋友页、AI 设置（联网查价、拍照识别等都在对话里）、撤销喝水等删除操作：置灰，点了提示「需要联网」 |

第二期再加：日记、快捷记餐模板（接口要先补 `client_id`）。

## 2. 读缓存
- 今天页自己把**本人**的 GET 结果存进 IndexedDB（库 `be-offline`）：`/v1/web/me`、`/v1/users/me/…`、`/v1/consent`、`/v1/explain/glossary`。**不存**别人的（`/v1/users/<id>/…`）、朋友页、AI 相关（`ai-*`、`assistant`）、心电图波形、反馈。
- 上限（`offline/params.py`，`offline.js` 里同一份，测试检查一致）：最多 300 条、约 4 MB、最长 14 天；超出先删最旧的；单条超过 1 MB 不存。按语言分开存（服务器文字跟 `X-Body-Lang`）。
- 断网冷启动：上次开关打开时留下的缓存（只有开关开着才会写）让页面先用缓存的 `/v1/web/me` 启动；联网后以服务器的开关为准，开关被关掉时先把队列发完再清空本机数据。
- 浏览器里原来的 service worker（`be-shell` / `be-data`，network-first）不变；页面自己的缓存在它之后兜底（SW 没有副本时返回 503 + `X-Offline`，页面再查 IndexedDB）。

## 3. 写入队列
- 只有带 `queue` 参数的写请求会进队列：网络错误时入队；队列里还有没发的，新写的也排到后面（不会插队）。
- 联网后（`online` 事件、任何一次 GET 成功、每 30 秒、横幅里「现在同步」）按顺序发送。
- 幂等和冲突：

| 类型 | 幂等 | 冲突怎么处理 |
|---|---|---|
| 喝水 `POST /water` | `client_id`（已有，`water_intake` 唯一约束）；带离线时点击的时间 `at`，补交后落在正确的那天 | 无冲突 |
| 训练逐组 `PUT /training/session/{day}` | 整份草稿覆盖，重发结果一样；同一天还没发的旧草稿被新的替换（合并成一条） | 以最后一次编辑为准（另一台设备同时改同一天，后同步的覆盖） |
| 训练提交 `POST …/submit` | 重复提交替换自己上次的记录 | 服务器发现当天已有相同动作（比如 AI 记过）→ 标成「没提交」，用户选「仍然提交」或「丢弃」 |
| 体重 `POST /weight`（新接口，开关管） | 同一天同一数值 = 没变化，不会重复写；同一天还没发的旧值被新的替换 | 当天已有不同数值 → 409，标成「没提交」，用户选「用这次的覆盖」或「丢弃」 |

- 失败：422 / 403 / 404 / 409 等 → 这一条标「没提交」并写原因，**同一组**（同一天的训练、同一天的体重）后面的等着，不会越过它；其他组照常发送。没网、401（登录过期）、429、5xx → 停下来，下次再试，不算失败。页面 toast「N 条离线记录没提交」+「查看」，横幅也一直显示，点开弹层可以重试 / 覆盖 / 丢弃。
- 队列最多 200 条，满了不再收，提示联网后再记。

## 4. 存储和隐私
- 全在本机（IndexedDB；浏览器另有 SW 的 Cache Storage），只存本人的数据；IndexedDB 打不开（隐私模式）时退回内存，只在这次打开期间有效。
- **退出登录**：清空 IndexedDB（读缓存 + 队列）和 SW 的 `be-data`；队列里还有没发的会先确认。
- **另一个账号登录**同一台设备：先清空上一个账号的全部数据。
- **401（登录过期）**：读缓存清掉；队列保留，同一账号重新登录后继续发。
- 开关关掉：下次联网打开时把队列发完、清空。

## 5. iOS app（WKWebView）
- **结论：app 里没有 service worker。** WKWebView 只在 app 声明 App-Bound Domains（Info.plist `WKAppBoundDomains` + `limitsNavigationsToAppBoundDomains`）时才开放 service worker；Watch2Whoop 没声明（服务器地址是设置二维码给的，不是固定域名；声明后还会限制 JS 注入和跳转），所以 `navigator.serviceWorker` 不存在，`sw.js` 在 app 里从来没生效过。
- 所以第一期的离线能力全部做在页面里（IndexedDB 在 WKWebView 里可用、跟着默认的持久化网站数据存储）。**app 已经打开着时断网**（最常见：地铁、电梯、信号差）不需要新版 app，部署服务器后对开了开关的人立刻生效。
- **断网时冷启动 app**：WKWebView 加载主页面失败，显示原生的「连不上今天页」。要在这种情况下也能看缓存 / 记录，需要 app 保存一份页面外壳，断网时用它打开（同源 baseUrl，能读到同一个 IndexedDB）。这要改原生代码 → 单独的 app PR，放进 1.0.7。

## 6. 上线
1. 合并、部署（`deploy/ali/push.sh code` → 重建 body-engine）。开关默认关，部署本身不改变任何人的页面（#77 的离线提示除外：只是网络失败时的文字和重试按钮）。
2. `body-engine flags set offline_mode --state cohort --cohort beta --by 管理员`。
3. 验收：打开今天页 → 飞行模式 → 横幅、缓存页面、喝水 / 体重 / 训练入队 → 关掉飞行模式 → 自动提交、数字正确、没有重复。
4. 通过后 `--state all`；稳定后删开关判断。
