# 薄肌模式（#126，开关 `slim_mode`）

> 状态：已实现，代码默认关；部署后只给负责人自己（用户 1）打开（分组 `owner`，不放量）。2026-10-27 负责人决定：做出来先自己体验；语录用三位真实人物（邵艾伦、孙宇晨、峰哥亡命天涯）公开发过的原话，不考虑版权。

## 1. 做了什么

| 部分 | 内容 |
|---|---|
| 主题 | 「我 → 外观」里选 默认 / 薄肌。只是 CSS 变量换配色加强调色（橙色），浅色和深色各一套（深色底 `#0a0a0b`、「好」的颜色是荧光绿；浅色底粉笔白），不改布局。立即生效；选择存服务端（表 `user_appearance`，迁移 900），换设备跟着账号走。 |
| 语录 | 薄肌主题下，今天页顶部一张小卡：一句话 + 人名 + 原帖链接。每天换一句（按用户本地日期，顺序固定打乱，所以同一个人不会连着出现），点一下换下一句，✕ 关掉（「外观」里可以再打开）。 |
| 开关 | `slim_mode`：关着时没有「外观」入口、接口 404、`/v1/web/me` 里没有 `appearance`、页面不加载 `slim.js`（也不加载语录）。上过薄肌的设备在开关关掉后启动时自动回到默认外观。 |
| 文件 | `web/static/slim.js`（主题 + 卡片 + 外观弹层，按需加载）、`web/static/slim-quotes.js`（语录数据，按需加载）、`appearance/`（存取和接口）、迁移 `900_appearance.sql`。首屏只多了 app.js 里的 4 处挂钩（约 500 字节）。 |
| 图标 | Lucide `quote`、`x`、`external-link`（`THIRD_PARTY_NOTICES.md`）。不用任何人的照片或头像。 |

接口：`GET / PUT /v1/users/me/appearance`（`{theme: "default"|"slim", quotes: bool}`，只能管自己、PUT 要 write 权限）；今天页启动时直接用 `/v1/web/me` 里的 `appearance`，不多发请求。

## 2. 语录的来源规则

- **每一条都是本人用自己的账号发过的原帖，一字不改**（不润色、不删减、不翻译；英文界面也直接显示原文）。数据里每条带 `source_url`（原帖链接）、`source_desc`、`posted`（发帖日期）、`verified: true`。
- 2026-10-27 入库前，逐条用 X 的公开接口（fxtwitter 镜像）重新取原帖核对：作者账号对得上、不是转发、文字一致；入库脚本自动断言，不靠人手抄。
- 找不到原始出处、只在网上流传或只在新闻里被转述的，放在同一个文件的 `unverified` 里：**页面不读它**，等负责人自己挑，找到原始出处后才能挪进 `items`。
- 健康方面：不放极端控水 / 极端减脂 / 贬低别人的句子；选的都是关于练、睡、赢、坚持的短句。这是内容选择，不是对原话的修改。
- 测试 `tests/test_slim_mode.py` 守住这些规则：每条 `verified` 为真、有指向本人账号的原帖链接、id 和链接里的帖子号一致、每个人都有、没有图片字段。

## 3. 以后要换成或加别的真实人物语录

负责人的决定是不考虑版权。如果以后这个 app 面向更多人（上架、商业化），需要重新评估：

1. **内容**：短句本身是否构成作品，由法务判断；越长越像作品，现在每条都是一两句。
2. **姓名 / 形象**：只写名字、不用照片；不能暗示本人代言。要用头像或肖像必须有本人书面授权。
3. **授权流程**：给本人（或其经纪方）发邮件，写明用途（app 里每天显示一句、带原帖链接）、范围（地区、期限）、是否收费；拿到书面同意后，在 `source_desc` 里记下授权日期和对方的确认方式；本人要求撤下时，从 `items` 删掉并发版。
4. **每条仍然要有原始出处**，不接受「网传」。
5. 商业版：语录数据放私有内容包，不进开源仓库（#126 讨论里的第 5 点）。

## 4. 部署（负责人决定后做，PR 里不做）

```
body-engine cohort add --user-id 1 --cohort owner --by 管理员
body-engine flags set slim_mode --state cohort --cohort owner --by 管理员
```

回退：`flags set slim_mode --state off`，下一次打开页面就回到默认外观；表里的选择保留。
