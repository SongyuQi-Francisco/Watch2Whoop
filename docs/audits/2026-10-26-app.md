### 2.2 问题与证据

**A1 — 线上版本落后（P1）**
- 证据：`apps/watch2whoop/CHANGELOG.md`。线上 1.0.6 不含 1.0.7 的修复：逐拍心率 / 心电图 / 饮水从未上传（#214）、站立 / 锻炼分钟等 12 类 OW SDK 读不到的类型（RawSync `quantities[]`）、同步中心、离线冷启动、按住说话、推送、`NotConfiguredException` 误报。`git diff app-ios-v1.0.7 origin/main -- apps/watch2whoop/ios` 为空，1.0.7 → main 的 iOS 相关改动只有 #289（Android 门控不改 iOS 行为）。
- 1.0.8 要带的「只在 main 修了」的问题：**#289**（OW 返回 401 时前台静默重连，退避 0 / 15 分钟 / 2 小时、每天最多 3 次；今天页「重新连接」一键链接）。线上已出现过 SDK 凭证失效、连续几天 401 无人发现。
- 现有兜底：页面 `sync-repair.js` 对 1.0.6 / 1.0.7 显示邀请码并打开「手机同步」，要用户手动操作。
- 建议：1.0.8 一次发到位（含 1.0.7 全部内容），发布说明里点名「1.0.6 用户请直接升 1.0.8」。

**A2 — 401 自愈覆盖面（P2）**
- 证据：`lib/src/raw_sync.dart` 的 `RawUpload.unauthorized` → `res.stop = 'unauthorized'`；账号 token 路径只在 `RawSyncStatus.problem` 里显示「登录失效，打开今天页后重试」，没有重新登录。`sync_repair.dart` 的触发条件是 `HealthSync.stats.authProblem`，它来自 `sync_stats.dart:116–140` 对 SDK 日志行（`HTTP 401`、`Token refresh rejected`、`auth is invalid`）的字符串匹配，SDK 改文案就会静默失效（已有测试，但只测当前文案）。
- 另：`HealthSync.connect()` 在换到新凭证后才 `signOut()`，但 `signOut()` 之后的 `configure/signIn` 若抛错，旧连接已丢、一次性邀请码也已用掉，自动重连失败时用户落到「未连接」。
- 建议：RawSync 401 且有账号 token 时，复用 `connectSyncViaAccount` 的静默换码路径换新的 ingest 登录；`connect()` 在 `signIn` 失败时给出明确提示并保留重试入口（不要停在未连接的静默状态）；日志匹配加一条「连续 N 次 upload 失败且无 2xx」的兜底。

**A3 — 弱网下 RawSync 久等（P2）**
- 证据：`RawSyncRunner._server()` 在 `status()` 返回 null（网络失败）时不记录失败，`serverStatus` 仍是 null，于是 water + 12 个注册类型每一类都会再发一次 `GET /v1/ingest/healthkit`，每次最长 `timeout`（60 秒）；预算检查（2 分钟）只在读页循环里。`SyncOnOpen` 在 `onDone` 完成前一直占着 `_running`。
- 复现：飞行模式以外的「连上 Wi-Fi 但无出口」（captive portal、被丢包的 VPN）状态下冷启动 app，观察同步页日志里 RawSync 一行的耗时（最坏十余次 × 60 秒）。本次未在真机复现，结论来自读代码。
- 建议：一次 pass 内第一次 `status()` 失败就记 `out.stop = 'offline'` 并 return；`status` 的超时单独设 10 秒。

**A4 — Podfile.lock 脱节（P2）**
- 证据：`ios/Podfile.lock` 最后一次更新是 #16；其中 `open_wearables_health_sdk (0.0.24)`、`mobile_scanner (7.0.0)`、`flutter_secure_storage_darwin (10.0.0)`，而 `pubspec.lock` 是 0.0.25 / 7.4.2 / 0.4.3（插件 11.2.0）。`pubspec.yaml` 注释写着「检查 `ios/Podfile.lock` 确认 OW iOS SDK ≥ 0.15（0.14 有同步竞态）」，现在这个检查对不上。
- 影响：发 TestFlight 时 `pod install` 会现场重写 lock，`OpenWearablesHealthSDK ~> 0.15.0` 可能浮动到别的 0.15.x，同一个 tag 两次构建结果可能不同。
- 建议：1.0.8 发版前在 Mac 上 `pod install` 并提交新的 lock；CI 加一项「`pod install` 后 `git diff --exit-code ios/Podfile.lock`」（macOS runner）或至少在发版清单里写上。

**A5 — 依赖告警（P2）**
- `.github/` 下没有 `dependabot.yml`（pub / Swift Pods / GitHub Actions / Python 都没有自动提示）。pub 的 advisory 机制只覆盖 pub.dev 上报的条目，CocoaPods 上的 OpenWearablesHealthSDK 不在内。
- 建议：加 `dependabot.yml`（`pub`、`github-actions`、`pip`/`uv`）；两个补丁版随 1.0.8 升（升后跑 `flutter test`）。

**A6 — 深链弹窗不显示目标（P2，仅非锁定构建）**
- 证据：`home_page.dart` `_onLink` 的对话框只说「会更新服务器地址 / 重新连接同步 / 重新登录今天页」，不显示新的服务器；`ServerLock.admit` 只在锁定构建（`W2W_LOCK_SERVER`）里拒绝别的服务器。`md.js` 只放行 `http(s)` 链接，所以今天页里 AI 回答 / 圈子帖子不能直接放出 `watch2whoop://` 链接，没有找到实际利用路径；扫码和粘贴是用户主动操作。
- 建议：非锁定构建的对话框里显示 `shortUrl(新地址)`；确认线上 TestFlight 构建是锁定构建（`config/defaults.json` 带 `W2W_LOCK_SERVER`）。

**A7 — 页面领先于 app（P2，排期依赖）**
- 页面代码已读取 `Watch2WhoopFeatures.voice`（`ai-media.js`、`jarvis-entry.js`，注释写「app 1.0.8+」）、`haptics`（`jarvis-entry.js`）、`net`（`app.js`）、`appleSignIn` / `appleLink`（`account.js`、`identities.js`）；app 的 `kFeaturesJs`（`web_mic.dart`）只宣布 `mic`、`syncCenter`、`syncRepair`，`lib/` 与 `ios/Runner/*.swift` 里没有对应实现。都有特性开关保护，所以现在不出错，是 1.0.8 的前置清单：这些能力不进 1.0.8 就应该确认页面不在默认路径上依赖它们。

### 3.2 加载与缓存

测量（本地 Playwright WebKit，冷启动）：

- 62 个请求：静态 40 个（JS 35 个、CSS 5 个）+ 入口 + 17 个 API；`/v1/users/me/today` 约 5.9 KB。
- 静态合计 1,242,015 字节，gzip 约 414,000 字节；最大的是 `app.js` 341 KB（gzip ≈ 107 KB）、`ai.js` 111 KB、`muscle-body-data.js` 105 KB、`i18n-en.js` 89 KB、`app.css` 87 KB。
- 线上 nginx 对 JS / CSS 做 gzip（`app.js` 341,964 → 122,712 字节），HTTP/2，没有 brotli。
- 缓存策略正确：带 `?v=<指纹>` 的静态文件 `immutable` 一年，入口和无指纹 URL 是 `no-cache`；app 的 WKWebView 不跑 SW（`sw.js` 注释已说明），重复打开只需入口 + API。

**W2 — 首屏体积（P2）**
- 估算（不是实测，Playwright WebKit 不支持网络限速，我用的串行延迟模拟会夸大，所以没有采用）：Slow 3G（约 400 kbps、RTT 400 ms）下冷启动静态 ≈ 450 KB gzip ≈ 9–10 秒传输 + 约 5 个 RTT 的依赖瀑布（入口 → 脚本 → 登录 / me → today）≈ 12 秒；热启动（指纹文件已缓存）≈ 入口 4.7 KB + 17 个 API 约 11 KB，2–3 秒，被 API 瀑布支配。每次发版只有改过的文件（指纹变了的）重下。
- 几乎所有人用不到却每次都下载的：`muscle-body-data.js` + `muscle-map.js` + `muscle-load.js`（137 KB，只在肌肉负荷图用）、`intro.js`（37 KB，只有首次引导用）、`i18n-en.js`（89 KB，中文用户不需要）。合计约 264 KB 原始 / ≈ 100 KB gzip，约占 24%。
- 17 个 API 里有 8 个是页面加载时同时打的小卡片接口（`stress`、`strain-coach`、`health-monitor`、`sleep-coach`、`training/day`…）；`login-code` → `me` → `today` 是串行链。
- 建议：上面三组改成按需加载（首次进入对应页面再 `import()` / 动态插入 `<script>`；`i18n-en.js` 只在英文时加载）；`/today` 把几个卡片接口的数据捎带进来省一轮 RTT；nginx 加 brotli（可选）。实测请在 Safari Web Inspector 的网络限速里再确认。

### 3.3 问题与证据

**W1 — Jarvis 回答里的链接在 app 内可能点不开（P1）**
- 证据：`md.js:27,30` 把 AI 回答里的 `[文字](https://…)` 和裸 https 链接渲染成 `<a target="_blank">`；同样 `ai.js:898`（`assistant_url` 的「打开」）、`feedback.js:47`（「公开链接」）。而团队自己在 `grocery.js:8`、`app.js:4122` 的注释里写明：在 iOS app 的 WKWebView 里 `<a target=_blank>` 什么也不做，`window.open` 才会到达 app 的导航代理并交给系统；超市链接已为此在 app 内去掉了 `target`，唯独 md.js 没有。没有任何全局点击拦截（搜 `closest("a")` 只有手册面板一处）。
- 复现（待真机 / 模拟器确认，我没有构建 app 实测）：app 内打开 Jarvis，让它回答一个带链接的问题（比如「给我一个 xx 的官方链接」），点链接。
- 建议：页面里加一个全局点击代理：在 app 内（`window.Watch2Whoop`）对 `a[target=_blank]` 执行 `preventDefault()` + `window.open(a.href, "_blank", "noopener")`。纯页面修复，1.0.6 / 1.0.7 也立刻生效。

**W3 — 趋势「1年」范围标签没有年份（P2）**
- 复现：趋势 tab → 点「1年」，卡片范围显示「10/27 → 10/26」，读成倒序。
- 建议：范围超过 6 个月时标签带年份（`2025/10/27 – 2026/10/26`）。

**W4 — 饮食 tab 依赖 SparkyFitness 的可用性（P2）**
- 复现：SparkyFitness 不可用时（本地环境就是），打开饮食 tab：显示「…」约 5–8 秒并弹「服务器正在更新，几秒后自动重试…」，重试 3 次后进入空状态；控制台 2 条 `Failed to load resource … 502`。记录 tab 同样先请求一次 `recipes/meal-plan`。
- 建议：`meal-plan` 失败不阻塞整页，先渲染其余卡片，该卡片局部显示「暂时读不到」；`#252`（去掉 SparkyFitness）完成后自然消失。

**W5 — 禁用缩放（P2）**
- `index.html` 的 viewport 带 `maximum-scale=1, user-scalable=no`。App Store 审核一般不拦，但违反 WCAG 1.4.4，视力不好的用户没法放大。建议去掉这两项（输入框字号 ≥ 16px 就不会触发 iOS 自动放大）。

**W6 — SW 预载重复下载（P2，浏览器入口）**
- 证据：`sw.js` 的 `SHELL_FILES` 用 `app.js` 这样不带 `?v=` 的 URL，页面本身用 `app.js?v=指纹`，两者缓存键不同，首访一次下 2 遍。app 的 WKWebView 不跑 SW，且 Safari 网页入口已计划退役，仅在保留浏览器入口时才值得修。

### 3.4 本地环境备注

- Body Engine 在 8190、`BODY_WEB_INSECURE_LOCAL_COOKIE=1`，库 `body_test_audit`（用 `quickstart/demo_data.py` 生成的合成数据，`import-apple-zip --no-scores` + `compute-scores`；没有 OW 时需要给 `BODY_OW_API_KEY_FILE` 一个占位文件，否则导入命令会因找不到 OW key 退出）。检查结束后已删库、停服务。
- 同一个用户同时跑两个浏览器会话会互相覆盖服务端的语言偏好（页面登录后以服务端为准）：做中英文对比时要串行跑，或每个语言一个用户。
