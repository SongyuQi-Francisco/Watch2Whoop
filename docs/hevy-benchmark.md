# 对标 Hevy：训练记录和朋友圈训练分享

> 状态：2026-10-22 调研 + 设计草案（issue #161），**等负责人确认第 7 节的决定后再开发**。导入 Hevy 数据单独一个 PR（第 6 节）。
> 合规：本文只参考 Hevy 的**交互和功能思路**；不复制它的图标、截图、文案、商标，界面文字全部自己写。下面对 Hevy 的描述是根据公开资料转述的，不是原文。

## 1. 为什么对标 Hevy
- Hevy 是目前最流行的力量训练记录 app 之一（iOS / Android / 网页 / Apple Watch / Wear OS），免费版就能无限记录，社交（关注、动态流、点赞评论、排行榜）是它的增长引擎。
- 我们的用户里练力量的人，第一个问题往往是「我原来在 Hevy 里的记录怎么办」「记一组要点几下」。
- 我们的差异化不在于再做一个 Hevy：**我们以 AI 记录为主、用手表数据（恢复、负荷、睡眠）给训练建议、默认隐私收紧**。所以对标的目标是：**在「自己动手记一次训练」这条路径上不比 Hevy 差**，社交上学它的「轻、正向」，不学它的「公开、陌生人」。

## 3. Hevy 的做法（转述）

### 3.1 训练记录
- **开始训练**：从空白开始，或从例行计划（routine）开始；计划可以分文件夹。也能把别人的训练「复制成一次训练」直接开练。
- **逐组记录**：每个动作一张卡，每组一行：组号、上次（PREVIOUS，可设为「这个动作上次」或「这个计划里上次」）、重量、次数、勾选完成。打勾即完成，上次的数字点一下就能填进去。
- **组类型**：点组号切换 正式 / 热身 / 递减组 / 力竭组；热身组不算进训练量和 PR。另有热身计算器（按百分比自动加热身组）。
- **RPE**：默认关，设置里打开后每组可以填 RPE。
- **计时**：整次训练有总时长；打勾后自动开始休息倒计时，可以按动作设默认休息时间，倒计时中可 ±15 秒；锁屏有 Live Activity，手表可以同步填组。
- **超级组**：动作菜单里把两个或更多动作配成超级组，完成一个自动滚到组里的下一个。
- **其他输入**：杠铃片计算器、按动作单位（kg / lb）、时长 / 距离类动作、动作笔记（只在这次）和计划笔记（每次都显示）。
- **个人纪录（PR）**：完成一组时实时提示新纪录（最重、预估 1RM、最多次数、最长时长等），需要在设置里打开。
- **结束和总结**：保存前可以改名、看总训练量和组数、改开始时间和时长、加照片 / 视频、写备注、设为私密；保存后显示这是第几次训练、连续周数、本次 PR，并给出分享入口。
- **动作库**：几百个动作（器械 / 肌群筛选、搜索），每个动作有演示动画和步骤；自建动作（免费版有数量上限）；动作详情里有历史、最重、预估 1RM、最佳一组、单次训练量、各组纪录。
- **统计**：按肌群的训练量、每周训练次数、单个动作的进步曲线（免费版只看最近一段）。

### 3.2 社交
- **关注**：单向关注；可以设私密资料（别人要申请关注、你同意后才看得到）。
- **动态流**：首页是关注的人的训练（标题、描述、时长、训练量、PR、照片 / 视频），可以点赞、评论、回复评论、给评论点赞；另有「发现」流看陌生人的训练（目前关不掉）。
- **单次训练的可见性**：保存时选公开 / 私密，也可以把「默认私密」设为全局。
- **分享**：保存后生成训练总结图（深色 / 浅色 / 透明底）分享到其他社交软件；例行计划可以用链接 / 图片分享。
- **比较和排行**：和某个人比训练次数、时长、训练量、共同动作的成绩；固定若干个动作的「好友排行榜」比最好成绩。
- **通知**：可以对某个人打开「他练完就通知我」。

### 5.1 我们应该学什么（汇总）
- **P0（第一期，4 件 + 导入）**
  1. Hevy CSV 导入（第 6 节）。
  2. 组类型：每组一个类型（正式 / 热身 / 递减 / 力竭），热身组不算训练量、不参与推荐重量和 PR。存在 `training_session_logs.exercises[].sets[].type`，提交时写进 SparkyFitness 的 set type（它本来就支持，规则引擎已经认 `WARMUP_SET_TYPES`）。
  3. 休息倒计时：勾选一组后在页面底部出现倒计时条（时长 = 计划的 `rest_sec`，没有就按动作类型的默认值，放 `training/params.py`），±15 秒、跳过；app 里倒计时结束震动一次（WKWebView 用 `navigator.vibrate` 不可用时走原生桥）。锁屏 Live Activity 放 P2（要原生代码）。
  4. 上次成绩逐组对照 + 一键填：每组行右侧灰字显示上次同一组（`60×8`），点一下填进重量和次数；推荐重量仍然优先（恢复分低时打折），两者不一样时用颜色区分。
  5. 训练结束总结：提交后弹一个总结层：时长（手表优先，否则页面的开始 / 结束）、总训练量、组数、本次 PR（P1 才有）、和上次同一训练的对比、今天的负荷；底部「分享」（P1）和「问 AI 点评」。
- **P1（第二期）**
  - 个人纪录（每个动作：最重、预估 1RM〔Epley〕、最多次数、最大单次训练量），提交时比对历史（含导入的 Hevy 历史）并在总结里列出；动作详情加个人历史曲线。
  - 训练中自由加动作（从动作库挑，禁用动作拦住），不改周计划。
  - 圈子内训练动态：朋友页加「训练」分段，按时间列圈子成员**已共享 training** 的训练（名称、时长、负荷等级、PR 个数，不列具体重量，除非对方额外共享「训练明细」）；对一次训练可以点 `👏 💪`（沿用 `circle_nudges` 的模型，加 `workout_ref`）。
  - 分享图：总结层「分享」生成一张图（canvas 本地画，不上传服务器），用户勾选放哪些字段（默认：训练名、时长、组数、PR 个数；重量、心率、恢复分默认不勾）；用我们自己的视觉。
  - 单次训练「不给圈子看」开关。
- **P2**：超级组视觉分组、热身 / 杠铃片计算器（先让 AI 回答）、文字评论（要举报 / 删除策略）、练完通知、复制朋友的训练、锁屏 Live Activity、绝对值之外的 PR 次数榜。

## 6. Hevy 数据导入（本期 P0，单独 PR）

### 6.1 导出格式（核实过的事实）
- 导出入口（Hevy 帮助中心）：个人 → 设置 → 导出和导入数据 → 导出数据 → 导出训练。得到一个 CSV。
- 官方帮助中心**没有列出列名**；列名以实际导出文件为准。公开仓库里的真实导出文件（mouadja02/Hevy-Coach 的 `workout_data.csv`）和另一个独立解析器（aree6/LiftShift 的类型定义）一致，表头是 14 列：
  `title, start_time, end_time, description, exercise_title, superset_id, exercise_notes, set_index, set_type, weight_kg, reps, distance_km, duration_seconds, rpe`
- 每行是一组；同一次训练由 `(title, start_time, end_time)` 确定；`set_index` 从 0 开始；`set_type` 是 `normal` / `warmup` / `dropset` / `failure`；时间形如 `30 Jun 2025, 19:56`（**本地时间、没有时区**）；空值是空字段。
- 用英制单位的账号，导出可能是 `weight_lbs` / `distance_miles`（第三方解析器都兼容这两种写法）：导入时都接受，换算成 kg / km。
- 时间格式也兼容 ISO 8601（有人用脚本转换过的文件）。

### 6.2 导入规则
- 入口：今天页「我 → 设置 → 导入 → 从 Hevy 导入」（开关 `hevy_import`，默认关）。上传 CSV（≤ 10 MB，大约十几万组），按用户鉴权，只能导给自己。
- 每次训练 → `workouts` 一行（`source = 'hevy'`，`external_id` = 开始时间 + 标题的 hash，类型 `strength_training`，按用户时区算 `local_date`）。如果手表在同一时段也有一次训练，按现有的去重规则（`refresh_duplicates`）保留手表那次（有心率），Hevy 那次标 `dup_of`，它的组挂到手表那次上显示。
- 组 → `training_session_logs`：加一列 `source`（`page` = 训练页自己记的，`hevy` = 导入的），主键改成 `(user_id, date, source)`，所以导入**永远不会覆盖**用户在训练页记的那天。导入的行 `status = 'imported'`，一天多次训练放在同一行里，每个动作带 `workout`（对应 `workouts.external_id`）。
- 动作名映射：先查用户自己的别名（以后手动对应的结果），再按动作库的英文名 / 别名 / 去掉括号里器械后的名字匹配；对不上的保留 Hevy 原名，`slug` 为空，`unmatched = true`，导入结果里列出来，之后可以手动对应。
- 幂等：同一个文件重复导入，结果不变；导入新的完整导出文件，旧训练原样、新训练加进来（按 `external_id` upsert；训练页记的那一天不动）。
- 导入完成：显示导入了几次训练、几组、几个动作没对上（列出名字）、跳过了几行（格式不对的行）。
- AI：`get_training_day` / `get_training_calendar` / 训练月历都能看到导入的训练和组（和 SparkyFitness 的训练一样合并到当天）。
- 负荷：导入后把受影响的天的 `daily_scores.muscle_load` 按「SparkyFitness 记录 + 导入的组」重算（热身组不算），每晚的完整评分也会带上导入的组。

2. **圈子训练动态默认显示到什么粒度**：建议默认只给「训练名、时长、负荷等级、PR 个数」，具体重量要对方再勾一个新的 scope（`training_detail`）。这会改同意书里共享范围的说明吗？如果要改，需要负责人改同意书版本。
3. **分享图**：确认「本地生成、不上传、默认不含重量 / 心率 / 恢复分」。
4. **导入的训练是否也写进 SparkyFitness**：建议**不写**（大量历史写进去慢，而且 SparkyFitness 只是记录后端）；导入的组只在 Body Engine 里，AI 和页面从这里读。代价：在 SparkyFitness 网页里看不到 Hevy 历史（我们本来就不让用户用 SparkyFitness 的界面）。
5. **P0 的范围**：第 5.1 节 4 件 + 导入是否就是下一期；休息倒计时的震动要不要等 iOS app 发新版（原生桥）。
