# iOS 原生 1.0.9：只能在真机上验证的项目（#340 N9）

> 给负责人和 TestFlight 内测组。模拟器回归见 [`ios-native-1.0.9-regression.md`](ios-native-1.0.9-regression.md)；模拟器做不到的（真的手表、后台调度、相机、麦克风、推送、120Hz、耗电、从 TestFlight 覆盖升级）都在这里。
> 每项写「步骤 → 预期」。不对的地方截图，在 #340 回复：哪一项、手机型号、iOS 版本、大概几点。截图里不要露出别人的数据。
> 「中控」那一列的检查要用服务器的命令，只有部署者能做。

## A. 安装和升级（最先做，负责人自己的手机）

| # | 步骤 | 预期 |
|---|---|---|
| A1 | 手机上现在是 TestFlight 的 **1.0.8**（Flutter 版），已经登录、同步正常。在 TestFlight 里点「更新」装 1.0.9，打开 | 不用重新登录，直接进今天页；顶部日期、三环有数（先是上次的缓存，再刷新）。Bundle ID 和 Team ID 和 1.0.8 一样，Keychain 访问组相同，才能读到 1.0.8 存的账号 token |
| A2 | 接上：打开「我 → 同步中心」 | 「同步正常」；首次同步不会从头再来（1.0.8 的同步锚点接着用）。中控：`rawdata_uploads` 里出现 `app_version = 1.0.9+10` 的批次，第一轮只有最近 48 小时的重复样本被服务器按 UUID 跳过 |
| A3 | 升级后第一次打开时弹出的东西 | 至多：一个「健康」授权窗口（补问 1.0.8 没问过的类型）、一次资料引导（可以「以后再说」）。**不应该**再弹同意书（已经同意过的人）；如果该弹同意书却没出现（回归报告 O1），记下来 |
| A4 | 退回测试：在 TestFlight 里装回 1.0.8 | 1.0.8 照常能打开、不用重新登录（原生版不删 Flutter 的 Keychain 项）。再装回 1.0.9 也照常 |
| A5 | 在原生版里「退出登录」，再用 1.0.8 打开 | 1.0.8 也要重新登录（退出登录时 Flutter 的 Keychain 项一起删掉，避免退回后出现一个已经吊销的会话） |
| A6 | 一台没装过的手机：从 TestFlight 公开链接装 1.0.9 | 登录页：通过 Apple 登录、邮箱验证码、扫设置二维码、激活码都在 |

## B. 登录

| # | 步骤 | 预期 |
|---|---|---|
| B1 | 通过 Apple 登录（新 Apple ID 和已绑定的各一次） | 系统的 Apple 登录面板弹出；已绑定的直接进；新的进「输入邀请码」或直接开通（看 `open_signup`） |
| B2 | 用 iPhone **系统相机**扫设置二维码（`deploy/open-wearables/invite.py --qr` 或开户包里的） | 弹出「用 Watch2Whoop 打开」，点了以后直接登录；已登录时先问「用这个设置信息重新登录？」 |
| B3 | 在 app 里点「扫码」 | 相机权限弹窗（说明是扫设置二维码、给 AI 拍照、拍头像）；扫到就登录 |
| B4 | 正在显示同意书 / 资料 / 健康权限那一步时，用系统相机扫另一个账号的二维码 | 先问「用这个设置信息重新登录？」；选「取消」后刚才那一步回来（回归 B5 修的） |

## C. 后台同步（至少两个人、两天）

| # | 步骤 | 预期 |
|---|---|---|
| C1 | 戴着手表正常过一天，**一整天不打开 app**；第二天早上打开今天页之前，先让中控看 | 中控：`sync_runs` 里有 `trigger = observer / refresh / processing` 的后台轮次；睡眠在起床后 1 小时内（手机解锁过）到服务器；心率、步数至少每 1–2 小时有一批。记下最长间隔 |
| C2 | 「设置 → 通用 → 后台 App 刷新」关掉 Watch2Whoop，过半天 | 同步中心说出「后台刷新被关」，并给去设置的按钮；打开 app 时照常同步一轮 |
| C3 | 锁屏续传：锁着屏放 2 小时（期间手表有新数据），然后只解锁、不打开 app | 解锁后几分钟内服务器收到这段数据（锁屏时读不到「健康」，解锁后续传）。中控：`sync_runs` 里有 `result = locked` 之后紧跟一次成功 |
| C4 | 断网续传：开飞行模式记一条喝水、一条日记，等 10 分钟再关飞行模式 | 两条都先显示（带时钟），联网后自动发出；「我 → 没提交的修改」变空 |
| C5 | 补全历史：同步中心 → 补全历史 → 近 90 天，然后锁屏 / 切走 | 后台接着补，进度会动；中途杀掉 app，下次打开从断点接着补；补完同步中心显示 100% |
| C6 | 低电量模式开着过半天 | 只同步重要的几项（睡眠、HRV、静息心率等），不报错 |
| C7 | 本机算分：新开户的内测用户，第一天同步完后 | 今天页三环下面出现「本机计算」；中控 `body-engine app-scores status --user-id N`：`active`、`trusted`，计划 `{"mode": "app", "days": []}`；`recent_checks` 里抽查通过。不一致时把 `diffs` 发到 #340 |
| C8 | 本机完整历史：重装 1.0.9 并登录，接电、连 Wi-Fi、锁屏放一晚 | 先恢复最近 60 天（几秒），更早的历史由系统安排的后台任务（`BGProcessingTask`，接电、空闲时）下载完，接着全部重算并上传；同步中心的「本机历史」进度到 100%。中控：`app-scores status` 计划仍是 `{"mode": "app", "days": []}`。模拟器没有这个系统调度，只能真机验 |
| C9 | 「我 → 数据状态」看本机存储，点「清除缓存」 | 显示本机占用（按年估算约 40 MB / 年）；清除后历史会重新下载，分数不丢 |

| # | 步骤 | 预期 |
|---|---|---|
| F1 | 今天页快速上下滚 | 没有明显卡顿；Instruments 里 hitch 比例 < 5 ms/s |
| F2 | 趋势页选「1 年」，快速滚过全部卡片；长按图表左右滑 | 第一次进屏的图表允许轻微掉帧，第二次滚动流畅；读数跟手 |
