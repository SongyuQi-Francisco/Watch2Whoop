# 朋友页（圈子与好友社交）设计

> 状态：2026-10-19 提出需求；**2026-10-22 负责人确认全部设计，开始开发**（分 3 个 PR，见第 8 节）。开发前的现状：底层已有按模块授权的 `shares` 表（[`001_init.sql`](../body_engine/src/body_engine/migrations/001_init.sql)）和「我 → 切换查看」弹层，但**没有**独立的「朋友」页、自助建圈子 / 邀请、多人同屏状态纵览，也没有排行榜。

## 1. 目标
1. **圈子**：用户自己建「家庭组 / 好友群」，邀请别人加入；被邀请人自己决定共享哪些数据。
2. **一屏纵览**：「朋友」页里看到每个人今天的状态和最近 7 天的状态。
3. **点进去看详情**：点成员卡片，进入对方的只读面板（复用现有按 `shares` 鉴权的今天 / 趋势 / 训练视图）。
4. **良性竞赛**：多维排行榜（身体状态、运动、认真生活），鼓励互相督促，认真睡觉、吃饭、锻炼。

## 2. 和已有产品 / 研究的对比

| 维度 | WHOOP Teams | Oura Circles | Apple Fitness 共享 / 竞赛 | 本方案 |
|---|---|---|---|---|
| 设备门槛 | 仅 WHOOP | 仅 Oura | 仅 Apple Watch | 自托管开源底座，先支持 Apple Watch，以后其他手表 |
| 点进成员看详情 | 仅榜单 | 仅分数卡片 | 圆环 + 简单运动记录 | 同屏卡片 + 按授权点进完整只读面板 |
| 排行维度 | 偏体能（Strain / Recovery / Sleep） | 无排行榜 | 只比圆环完成度 | 三个榜：身体状态、运动、认真生活（作息 + 饮食） |
| 公平性 | Strain 0–21 归一化 | — | 按各自卡路里目标的百分比 | 全部相对个人基线 / 个人目标，老少同场 |
| 隐私粒度 | 进组即公开三大分数 | 可选公开哪几个分数 | 统一公开圆环与训练类型 | 按模块授权（`shares.scopes`），饮食可只共享达标率 |
| AI 联动 | 无 | 无 | 无 | 授权范围内让 AI 总结家人近况 |

研究依据（实现前再核对原文）：针对 Fitbit 排行榜的实证研究（*Management Science*）显示，排行榜对久坐用户帮助最大，对原本很活跃的用户可能反而降低活动量；mHealth 游戏化综述也指出，纯外在竞争会削弱长期内在动机，合作 / 小圈子互助更稳。因此本方案：**按个人基线比、恢复和作息也计分、小圈子熟人、不鼓励刷运动量**。

## 3. 功能设计

### 3.1 入口（2026-10-19 已确认：方案 B）
- 底部仍保持 5 个 Tab：`今天` / `趋势` / `朋友` / `记录` / `我`。
- `饮食`（食谱、采购清单）并入 `记录` 页，作为其中一个分段（`记录 | 饮食`）；原来的 `#food` 链接继续可用，打开「记录 → 饮食」。
- 界面遵循 v2.10 的原则：只放数字、图表、短标签，不放解释句。

### 3.2 圈子与邀请（2026-10-22 已确认）
- 任何已同意同意书的用户都可以建圈子（名称自定，每人最多建 / 加入的圈子数见 `friends/params.py`）。
- 邀请：圈主生成邀请码 / 链接 `…/app/?circle=CODE`（二维码由 app 生成），**有效期圈主自己选（1 / 3 / 7 / 30 天或永久有效，默认 3 天，#156）**，可以随时单个「作废」或全部「重置」（旧码立即失效）。邀请码只存 sha256，明文只在生成 / 重置时出现一次。
- 加入时弹层让本人勾选共享范围（按 scope），**默认勾选**：
  - `scores`、`sleep`（评分：恢复、睡眠、负荷等）
  - `training`（训练）
  - `nutrition_summary`（新的轻量 scope：只给每天的**热量 / 蛋白达标与否和达标率**，不给吃了什么、吃了多少）
- **默认不勾**（适合直系亲属，自己决定）：`nutrition`（具体饮食）、`weight`（体重）、`labs`（化验）、`supplements`（补剂）、`journal`（日记）、`memory`（长期记忆）；以及 `metrics`、`events`。
- **心电图（`ecg`）永远不进圈子共享**：圈子的可选范围里没有它，接口传了也拒收；要给某个人看心电图仍走单独授权。
- 共享写进 `shares`：两人每有一个共同圈子，就把「我在这个圈子里选的 scope」给对方；多个共同圈子**取并集**。现有 `/v1/users/{user}/*` 的按块鉴权不用改。
  - 由圈子产生的部分单独记在 `shares.circle_scopes`，和管理员手动开的 `shares.scopes` 分开：改范围 / 退出 / 被移出 / 圈子解散时只重算 `circle_scopes`，**立即生效**，不会误删手动授权。
- 随时可以改共享范围、退出圈子（圈主可以移除成员、解散圈子）。符合 [`family-consent.md`](family-consent.md) 第 2、3 节。
- **同意书「圈子共享」一条**：在负责人定稿的同意书 2026-10-22.2 第 2 节里（单独的 PR #129，对所有用户生效）；建圈子 / 加入圈子要求同意过这一版或更新的版本，否则先在 app 里重新确认。
- **用户自己的邀请码（#57）接上圈子**：好友用我的个人邀请码注册成功后，自动收到「加入我建的圈子」的邀请（`circle_invites.invitee_user_id`，30 天有效）；对方在朋友页看到邀请，**共享范围还是由他自己选**，不点就不加入、不共享任何东西。`invite_redemptions.circle_id` 记下第一个邀请的圈子。
- **个人圈子（方案 A，负责人 2026-10-22 定）**：每人一个自己的圈子（「Ann 的圈子」，圈主是本人，`circles.personal`），**第一次用到圈子时补建**（`friends` 开关对他开着 + 已确认同意书 2026-10-22.2；迁移 575 不回填，因为迁移看不到每个人的开关和同意书），新用户、老用户同一条路。已经自己建过圈子的人不再建，原来的圈子不动，最早建的那个就是他的「主圈子」；`users.personal_circle_at` 记一次，解散了不会再自动建。推荐注册的邀请只发到邀请人的**主圈子**（不再发到他建的每个圈子），所以 A 邀请 B、B 邀请 C 时，C 进的是 B 自己的圈子，A 和 C 互相看不到。
- **新手引导（`intro.js`，跟 `friends` 开关，新旧两种视觉都有）**：开关开着的人多两屏「邀请好友」（邀请码在哪）和「朋友圈子」（共享什么、怎么改、怎么退出）；用推荐码注册的人再多一屏「加入 XX 的圈子」（`GET /v1/friends/referral`）：默认勾选「加入」、共享默认范围，点「下一步」才加入，取消勾选或跳过就不加入（邀请留在朋友页）。邀请人或被邀请人有一方开关没开：不建圈、不发邀请、不报错；两边都开之后（被邀请人打开引导或朋友页时）补发邀请。

### 3.3 成员卡片（今天 + 最近 7 天）
- **今天**：首字母头像、称呼、状态短标签（沿用恢复分三档：适合高强度 / 按计划训练 / 以恢复为主）、今天三个数（恢复、睡眠、负荷）；今天已训练显示徽章；今天没同步显示「上次同步 日期」。
- **最近 7 天**：一排 7 个小圆点（每天恢复分的绿 / 黄 / 红 / 灰）+ 7 根迷你柱（每天负荷）。
- 每一块按 scope 鉴权：对方没共享 `scores` 就不显示这三个数和圆点，只显示「未共享」短标签。
- 轻互动：每天对同一个人可以点一次 `👏` / `💤` / `💪`（每种各一次），对方在自己的卡片上看到今天收到的数量；不开放自由文字。

**v2 改版（2026-10-22，灰度开关 `friend_card_v2`，关着时是上面的旧版）**：旧版那排 7 个没有标注的灯被误读成「今天的状态」（三个黄灯 ≠ 今天不好），所以改成：
- 第一行：称呼 + 今天的恢复分（大号、按区间着色）+ 状态短标签；第二行：恢复 / 睡眠 / 负荷三个带标签的数，今天练过加「已训练」。
- 「近 7 天恢复」趋势条：只显示恢复，每个灯下面标星期几、今天那个高亮，点一天弹出那天的恢复、睡眠、负荷（数据来自卡片 `week[]`：`weekday`、`today`、`recovery`、`sleep_min`、`sleep_score`、`strain`）。
- 没共享 `scores`：灰色「未共享」，数字和趋势条都不出现；共享了但今天没同步：灰色「未同步 · 上次 10-21」（不留空、也不显示成 0）。
- 自己的卡片放最上面，标「朋友看到的你」：按我给圈子里所有人的共享范围的**并集**显示（`me.seen`：`scopes`、`hidden`、`count`、`varies`）；各人看到的不一样时卡片上说明「按所有人的并集显示」，还没有朋友时显示完整卡片并提示「加入圈子后朋友才看得到」。
- 👏 / 💤 / 💪 在卡片右下角，点一下就发（规则不变）；点卡片其他地方进入对方的只读页面。

### 3.4 排行榜（2026-10-22 已确认）
**核心原则：比的是和自己基线相比的进步 / 状态，不比绝对值**，体能、年龄、体重差别很大的人也能公平同场。所有权重、窗口、阈值都在 `friends/params.py`，可以配置，写明出处。

- 窗口：**近 7 天滚动**（截止今天的最近 7 天，随时看，不按自然周清零）；**抗衰老榜用 4 周窗口**（身体年龄 / 衰老速度变化慢）。
- 每个榜 0–100 分，只显示分数、名次和副标签（如「绿灯 5/7」），不显示体重、热量等绝对值。
- 只有对方给我共享了该榜需要的**全部** scope 才上榜；没共享的显示「未共享」、数据不够的显示「数据不足」，都**不算垫底**、不排名次。
- 数据不足的规则：有效天数不够（见下表）或个人基线不够时不排名。

| 榜 | 需要的 scope | 分数（0–100） | 副标签 | 导向 |
|---|---|---|---|---|
| 身体状态（默认） | `scores` | 60% × 7 日平均恢复分 + 40% × 7 日平均睡眠表现（实际睡眠 / 自己的睡眠需求，封顶 100）；至少 4 天有效 | 绿灯天数、睡眠均值 | 恢复分本身就是相对自己 HRV / 静息心率基线的；熬夜透支反而掉榜 |
| 运动 | `scores` + `training` | 70% × 负荷比得分 + 30% × 训练天数得分。负荷比 = 近 7 天负荷 ÷ 自己前 28 天的周平均；0.8–1.3 满分，> 1.5 起扣分（急慢性负荷比，Gabbett 2016）；训练天数 4 天满分（WHO 2020：每周多数天活动 + 至少 2 天力量） | 训练天数、负荷比 | 比自己平时练得积极，不鼓励猛加量 |
| 认真生活 | `sleep` + `nutrition_summary` | 50% × 按时睡命中率 + 50% × 饮食达标率。按时睡 = 入睡时间在自己的入睡目标内（没设目标就用自己前 28 天的中位入睡时间 ± 45 分钟）；饮食达标 = 当天热量在自己目标 ± 10% 且蛋白 ≥ 目标 90%（沿用 `rules/params.py`），没记 = 不达标 | 按时睡 n/7、饮食达标 n/7 | 不爱剧烈运动但作息、饮食认真的人也能拿第一 |
| 瘦体增肌 | `weight` + `training` + `nutrition_summary` | 40% × 体重 / 体脂往自己目标走 + 40% × 训练量 / 力量进步 + 20% × 蛋白达标。体重：近 7 天均值 vs 前 7 天均值，往目标方向每周 0.5–1% 体重满分（减脂，Helms 2014）/ 0.25–0.5%（增肌，Iraki 2019），太快扣分；已在目标 ± 1 kg 内按维持算。训练：近 7 天力量训练量（组 × 次 × 重量）÷ 自己前 28 天周平均，≥ 1.0 满分 | 往目标的速度（%/周）、训练量比 | 减脂期不掉肌肉、增肌期不乱吃；体重默认不共享，所以只有自己选了共享体重的人才上榜 |
| 抗衰老（4 周窗口） | `scores` | 60% × 4 周里身体年龄差（身体年龄 − 实际年龄）的变化（年轻 1 岁 = 100、不变 = 50、老 1 岁 = 0）+ 40% × 当前衰老速度（0.5 = 100、1.0 = 50、1.5 = 0）；要有 4 周前和本周的周快照 | 身体年龄差变化、衰老速度 | 长期习惯，变化慢所以窗口长 |

- 实现细节（PR C）：饮食类（认真生活、蛋白达标）按**截止昨天**的 7 个完整日算（今天还没吃完）；瘦体增肌的体脂只在本人两个 7 天窗口都有体脂记录时参与（和体重分取平均）；抗衰老在衰老速度还算不出来（不到 8 周）时只用身体年龄差的变化；没有入睡目标时，按时睡 = 在自己前 28 晚中位入睡时间 ± 45 分钟内；读不到 SparkyFitness 的人显示「数据不足」。
- 研究依据（见第 2 节）：排行榜对原本活跃的人可能有反作用，所以全部按个人基线、运动榜封顶并惩罚猛加量、恢复和作息也计分。
- 不是医疗设备：榜单只用于鼓励；恢复分低的人不展示「落后」字样。

### 3.5 点进成员详情
- 点卡片 → `S.owner` 切到该成员，进入其只读「今天」页（可再看趋势、训练月历）；顶部常驻「正在查看：XX（只读）· 返回」。
- 沿用 `views.section()` 逐块鉴权，未共享的块不显示；所有写入口（记餐、改目标、写日记、勾补剂、开训练、AI 对话）查看他人时隐藏。

### 3.6 AI 联动
- 新增只读工具 `get_friends_overview`：只读已授权圈子成员的摘要（状态短标签、近 7 天均值、榜单名次），可问「家里这周谁恢复得最好」。描述要短（工具定义总长度有预算，`tests/test_briefing.py`）。
- 不越过授权（同样按 scope 逐块）；托底 AI 不开放这个工具（只读本人数据）。

## 4. 数据与接口

新迁移（编号 ≥ 470，开发时确认没被占）：
- `circles (id, name, owner_id, created_at)`
- `circle_members (circle_id, user_id, scopes TEXT[], joined_at, PRIMARY KEY (circle_id, user_id))`：`scopes` 只能是 `friends/params.CIRCLE_SCOPES` 里的（不含 `ecg`）。
- `circle_invites (id, circle_id, created_by, code_sha256 UNIQUE NULL, invitee_user_id NULL, expires_at, revoked_at, used_count, created_at)`：邀请码（有效期自选，`expires_at` 为空 = 永久有效，迁移 605）或指定用户的邀请（#57 推荐注册，30 天）。
- `shares` 加列 `circle_scopes TEXT[] NOT NULL DEFAULT '{}'`；鉴权看 `scopes`（手动，受 `expires_at` 约束）∪ `circle_scopes`。
- `circle_nudges (id, from_user_id, to_user_id, kind, date, created_at, UNIQUE (from_user_id, to_user_id, kind, date))`：只能发给和自己有共同圈子的人。
- 都不 `GRANT` 给 `grafana_ro`（不是健康数据）。

| 接口 | 说明 |
|---|---|
| `GET /v1/friends` | 我的圈子、成员、我在每个圈子的共享范围、待处理的邀请 |
| `POST /v1/friends/circles` | 建圈子（同时返回第一张邀请码） |
| `POST /v1/friends/circles/{id}/invite` | 圈主生成 / 重置邀请码（`reset=true` 让旧码全部失效） |
| `POST /v1/friends/join` | 凭邀请码（或指定邀请 `invite_id`）加入，提交自己的 `scopes` |
| `PATCH /v1/friends/circles/{id}/me` · `DELETE …/me` | 改共享范围 / 退出 |
| `DELETE /v1/friends/circles/{id}/members/{user}` · `DELETE /v1/friends/circles/{id}` | 圈主移除成员 / 解散 |
| `GET /v1/friends/overview` | 成员卡片（今天 + 近 7 天，按 scope） |
| `GET /v1/friends/leaderboard?board=` | 排行榜（PR C） |
| `POST /v1/friends/nudges` | 一键鼓励 |

## 5. 隐私与安全要点
- 邀请码只存 sha256，有效期自选、可作废 / 重置；加入失败按 IP / 用户限次数（沿用 `web/login_limit.py` 的做法）。
- 写操作只能对自己；圈主只能移除成员、不能改别人的共享范围；`nudges` 只能发给同圈成员。
- 圈子成员不是管理员，看不到未授权的任何数据；退出 / 被移出 / 解散时**立即**收回由圈子产生的共享。
- 心电图永远不进圈子；AI 配置、反馈、AI 对话本来就不在 shares 里。
- 建圈子 / 加入要求同意过含「圈子共享」一节的同意书版本。

## 6. 范围外 / 以后再说
自由文字聊天、公开 / 陌生人社区、跨服务器好友、奖励 / 虚拟货币、按团队对抗赛。

## 7. 验收要点
- 新用户建圈、邀请、加入、改 scope、退出全流程，授权即时生效。
- 跨用户越权测试：没共享看不到；退出 / 被移出后马上看不到；心电图在任何情况下都看不到；手动授权不被圈子操作误删。
- 未共享的 scope 在卡片、榜单、详情、AI 工具里都不泄露。
- 榜单对数据不足、时区、只同步了部分天的情况给出合理结果（不排名、不垫底）。
- 中英双语（`tr()` / `i18n-en.js`）；截图中英各一套。

## 9. 圈子训练动态（2026-10-22，灰度开关 `circle_feed`，需要同时开 `friends`）

朋友 tab 的分段是「成员 | 动态 | 排行榜」（开关关着时没有「动态」）。代码：`friends/feed.py`、`feed_api.py`，前端 `web/static/circle-feed.js`，迁移 `635_circle_feed.sql`。

- **自动发，不弹窗**：谁给某个圈子勾选了「训练」共享，他当天的训练就自动出现在这个圈子的动态里，一天一条（`circle_feed_posts` 只是给 ❤️ 和评论用的锚点，内容每次读取时从 `training_session_logs`（打了勾的组）和 `workouts` 现算，所以当天新增的组会更新进去）。没勾「训练」的人不会出帖；同意书不变（沿用「圈子成员能看到我勾选的内容」）。
- **帖子内容**：训练名、时长、动作列表（默认前 3 个，可展开）、每组的次数和重量、组数、总负荷（kg = 次 × 重量，只算打勾的组）、🏆 个人纪录（某动作今天的最大重量超过之前所有天；第一次做不算）。不含心电图、化验、体重。
- **不能删除**：没有删除 / 修改帖子的接口。谁能看是每次读取时按「同圈 + 作者在该圈勾选了训练 + `auth.can_view`」算的，所以退出圈子后对方立即看不到（对方在别人帖子下的评论和 ❤️ 也不再显示）；重新加入又会出现。
- **❤️**：`PUT|DELETE /v1/friends/feed/posts/{id}/like`，和 👏 / 💤 / 💪（`circle_nudges`）互不相干。取消后再点不会再次通知作者。
- **评论**：只能文字（单行，最多 300 字，每人每小时 30 条）；写的人自己能删（软删除，留着给举报）；任何同圈的人可以举报（`circle_feed_reports`，每人每条一次，自己的不能举报）。帖子作者不能删别人的评论，只能举报。
- **红点**：`GET /feed/unread`（自上次打开动态后别人在我的帖子上的 ❤️ + 评论数），朋友 tab 和「动态」分段上显示；打开动态时 `POST /feed/seen` 清掉。页面开着时每分钟刷新一次。
- **通知**：有人 ❤️（第一次点）/ 评论时直接调用 `notify.notify(...)` 通知帖子作者（kind = `circle.like` / `circle.comment`，属于通知设置里的「圈子互动」；给自己的帖子点赞 / 评论不通知）。跳转链接 `/app/?tab=friends&feed=<帖子 id>`：打开朋友 tab 的「动态」，滚到那条帖子并展开评论（`circle-feed.js` 监听 `body:link`）。
- 接口：`GET /v1/friends/feed?before=&limit=`（`before` = 上一页返回的 `next`，按日期倒序，往下滑加载更多）、`GET|POST /feed/posts/{id}/comments`、`DELETE /feed/comments/{id}`、`POST /feed/comments/{id}/report`。
