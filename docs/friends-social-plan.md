# 朋友页（家庭组与好友社交）需求草案（以后的版本，暂不做）

> 状态：2026-10-19 提出需求，只立项、不开发。现状：底层已有按模块授权的 `shares` 表（[`001_init.sql`](../body_engine/src/body_engine/migrations/001_init.sql)）和「我 → 切换查看」弹层，但**没有**独立的「朋友」页、自助建圈子 / 邀请、多人同屏状态纵览，也没有排行榜。

## 1. 目标
1. **圈子**：用户自己建「家庭组 / 好友群」，邀请别人加入；被邀请人自己决定共享哪些数据。
2. **一屏纵览**：「朋友」页里看到每个人今天的状态和最近 7 天的状态。
3. **点进去看详情**：点成员卡片，进入对方的只读面板（复用现有按 `shares` 鉴权的今天 / 趋势 / 训练视图）。
4. **良性竞赛**：多维排行榜（身体状态、运动、认真生活），鼓励互相督促，认真睡觉、吃饭、锻炼。

## 2. 和已有产品 / 研究的对比

| 维度 | WHOOP Teams | Oura Circles | Apple Fitness 共享 / 竞赛 | 本方案 |
|---|---|---|---|---|
| 设备门槛 | 仅 WHOOP | 仅 Oura | 仅 Apple Watch | 自托管开源底座，先支持 Apple Watch，以后其他手表 |
| 点进成员看详情 | 仅榜单 | 仅分数卡片 | 圆环 + 简单运动记录 | 同屏卡片 + 按授权点进完整只读面板 |
| 排行维度 | 偏体能（Strain / Recovery / Sleep） | 无排行榜 | 只比圆环完成度 | 三个榜：身体状态、运动、认真生活（作息 + 饮食） |
| 公平性 | Strain 0–21 归一化 | — | 按各自卡路里目标的百分比 | 全部相对个人基线 / 个人目标，老少同场 |
| 隐私粒度 | 进组即公开三大分数 | 可选公开哪几个分数 | 统一公开圆环与训练类型 | 按模块授权（`shares.scopes`），饮食可只共享达标率 |
| AI 联动 | 无 | 无 | 无 | 授权范围内让 AI 总结家人近况 |

研究依据（实现前再核对原文）：针对 Fitbit 排行榜的实证研究（*Management Science*）显示，排行榜对久坐用户帮助最大，对原本很活跃的用户可能反而降低活动量；mHealth 游戏化综述也指出，纯外在竞争会削弱长期内在动机，合作 / 小圈子互助更稳。因此本方案：**按个人基线比、恢复和作息也计分、小圈子熟人、不鼓励刷运动量**。

## 3. 功能设计

### 3.1 入口（2026-10-19 已确认：方案 B）
- 底部仍保持 5 个 Tab：`今天` / `趋势` / `朋友` / `记录` / `我`。
- `饮食`（食谱、以后的采购清单）并入 `记录` 页，作为其中一个分段。
- 界面遵循 v2.10 的原则：只放数字、图表、短标签，不放解释句。

### 3.2 圈子与邀请
- 任何登录用户可建圈子（名称自定），生成邀请码 / 二维码 / 链接（默认 72 小时有效，可重置）。
- 加入时弹层让本人勾选共享范围（写入 / 同步 `shares`，取两人所有共同圈子 scope 的并集，现有 `/v1/users/{user}/*` 鉴权不用改）：
  - **默认推荐**：`scores`、`sleep`、`training`，和新增的轻量 scope `nutrition_summary`（只给热量 / 蛋白**达标百分比**，不给吃了什么）。
  - **可选（适合直系亲属）**：`nutrition`、`weight`、`labs`、`supplements`、`events`、`memory`。
- 随时可改共享范围或退出，立即生效（符合 [`family-consent.md`](family-consent.md) 第 4、5 节）。同意书要加「圈子共享」一节，改版后须与 `body_engine/src/body_engine/profile/consent.md` 一字不差并升版本号。

### 3.3 成员卡片（今天 + 最近 7 天）
- **今天**：头像、称呼、状态短标签（沿用恢复分三档：适合高强度 / 按计划训练 / 以恢复为主）、今天三个数（恢复、睡眠、负荷）；今天已训练显示徽章；今天没同步显示「上次同步 日期」。
- **最近 7 天**：一排 7 个小圆点（每天恢复分的绿 / 黄 / 红 / 灰）+ 7 根迷你柱（每天负荷）。

### 3.4 排行榜（2026-10-19 已确认：近 7 天滚动窗口）
窗口 = 截止今天的最近 7 天，随时看，不按自然周清零。顶部分段切换三个榜：

| 榜 | 排名指标 | 副标签 | 导向 |
|---|---|---|---|
| 身体状态榜（默认） | 7 日平均恢复分（至少 4 天有效数据才上榜） | 睡眠均值、绿灯天数 | 谁把身体照顾得最好；熬夜透支反而掉榜 |
| 运动榜 | 7 日有效负荷（个人归一化的 Strain）+ 训练天数 | 训练次数、活动消耗 | 谁最近练得积极，不同体能同场 |
| 认真生活榜 | 自律分 = 入睡目标命中率 50% + 饮食达标率 50% | 按时睡 n/7、饮食达标 n/7 | 不爱剧烈运动但作息饮食认真的人也能拿第一 |

- 只有双方都共享了对应 scope 的人才进该榜；没共享的显示「未共享」，不算垫底。
- 轻量互动：每天对同一人可点一次 `👏 棒` / `💤 早点睡` / `💪 一起练`，不开放自由文字聊天。

### 3.5 点进成员详情
- 点卡片 → `S.owner` 切到该成员，进入其只读「今天」页（可再看趋势、训练月历）；顶部常驻「正在查看：XX（只读）· 返回朋友页」。
- 沿用 `views.section()` 逐块鉴权，未共享的块不显示；所有写入口（记餐、改目标、写日记）查看他人时隐藏。

### 3.6 AI 联动（可选）
- 新增只读工具 `get_friends_overview`，只读已授权圈子成员的摘要，可问「家里这周谁恢复得最好」。
- 不越过授权；托底 AI 默认仍只读本人数据，除非用户单独确认（见同意书第 4 节）。

## 4. 数据与接口草案

新迁移 `body_engine/src/body_engine/migrations/NNN_social_groups.sql`（有 `user_id` 的表按约定带 `user_id`；Grafana 要读再 `GRANT SELECT ... TO grafana_ro`）：
- `social_groups (id, name, created_by, invite_code_sha256, invite_expires_at, created_at)`
- `social_group_members (group_id, user_id, scopes TEXT[], joined_at, PRIMARY KEY (group_id, user_id))`
- `social_nudges (id, group_id, from_user_id, to_user_id, kind, date, created_at)`，每人每天对同一人同一类限一次

| 接口 | 说明 |
|---|---|
| `GET /v1/friends/overview?group_id=` | 圈子列表、成员今日摘要、近 7 天序列、三个榜 |
| `POST /v1/friends/groups` | 建圈子，返回邀请码 |
| `POST /v1/friends/groups/join` | 凭邀请码加入，提交自己的 `scopes` |
| `PATCH /v1/friends/groups/{id}/me` · `DELETE` | 改共享范围 / 退出 |
| `POST /v1/friends/nudges` | 发一键鼓励 |

排行阈值和权重放 `friends/params.py` 并写明出处，保持可配置，不写死某个人的数据。

## 5. 隐私与安全要点
- 邀请码只存 sha256，限次数 / 限时，失败有速率限制（参考 `web/login_limit.py`）。
- 写操作只能对自己；`nudges` 只能发给同圈成员。
- 圈子成员不是管理员，不能看到未授权的任何数据；退出圈子时同步收回由该圈子产生的 `shares`。
- 不是医疗设备：榜单只用于鼓励，不据此给医疗建议；恢复分低的人不展示「落后」字样。

## 6. 范围外 / 以后再说
自由文字聊天、公开 / 陌生人社区、跨服务器好友、奖励 / 虚拟货币、按团队对抗赛。

## 7. 验收要点（开发时）
- 新用户建圈、邀请、加入、改 scope、退出全流程，授权即时生效。
- 未共享的 scope 在卡片、榜单、详情里都不泄露（接口测试覆盖）。
- 榜单对数据不足、时区、只同步了部分天的情况给出合理结果。
- 英文 UI 前，所有用户可见文字 Chinese-first；代码注释和开发文档用英文。
