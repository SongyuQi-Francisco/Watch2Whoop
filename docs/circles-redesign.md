# 圈子重构方案（v0.1，2026-10-25）

> 依据：[`circles-research.md`](circles-research.md)（同类产品调研）和现有实现（`friends/`、`web/static/circles.js`、`circle-feed.js`、
> [`friends-social-plan.md`](friends-social-plan.md)）。Issue：#269。第 9 节是要负责人决定的点。
> 原则不变：手机优先、按用户鉴权、心电图永不进圈子、界面只放数字 / 图表 / 短标签、中英双语。

## 1. 目标

1. 朋友页**按圈子分开**：每个圈子有自己的成员、动态、排行榜；另有「全部」做汇总。
2. 一个人在很多圈子里时**好切换、好管理**：置顶、最近、静音、归档、搜索。
3. **角色**：圈主 / 管理员 / 成员；成员也能邀请，圈子可以要求审批。
4. **邀请链**：每个成员是谁邀请的、通过哪个码 / 链接、什么时候进来的；圈主和管理员看得到，成员之间看不到。
5. **隐私**：每个圈子单独设分享范围，默认最少；各圈视图只按该圈的范围显示。
6. **扩列和社群的平衡**：只在熟人邀请链上扩，不做陌生人发现。

## 2. 信息架构（朋友 tab）

```
朋友
├─ 圈子切换条：[全部] [置顶圈 1] [置顶圈 2] … [▾ 更多]      ← 横向滑动；「更多」打开圈子抽屉
├─ 选了「全部」
│   ├─ 成员：按圈子分组的折叠段（每段：圈子头像 + 名字 + 人数），同一个人在多个圈子里只在第一个出现的段里显示完整卡片，其余段显示小头像
│   ├─ 动态：所有未静音、未归档圈子的帖子合并，每条帖子标出来自哪个（些）圈子
│   └─ 排行榜：不提供跨圈排行，显示「选一个圈子看排行榜」+ 最近用过的圈子快捷按钮
└─ 选了某个圈子 C
    ├─ 头部：圈子头像、名字、人数、我在这个圈子共享了什么（一行标签）、⋯（圈子设置）
    ├─ 成员 | 动态 | 排行榜：只含 C 的成员；数据只按每个人在 C 里勾选的范围显示
    └─ 圈主 / 管理员多一个「管理」入口：成员（含入圈记录）、邀请、审批、角色
```

为什么「全部」不排行：不同圈子的人互不认识，混排没有意义（调研 §3 不借鉴第 2 条）；但「全部」的动态保留，因为看朋友训练本来就是跨圈的。

### 2.1 按圈子的可见性（关键改动）

现在两个人之间的授权是跨圈子并集（`shares.circle_scopes`），这一层**保留**：它回答的是「B 一共能看 A 的什么」，用于点开 A 的只读页。
新增的是**视图层按圈过滤**：

| 视图 | 现在 | 改后 |
|---|---|---|
| 圈子 C 的成员卡片 | 所有共同圈子的人、并集范围 | C 的成员；每人只显示他在 C 里勾选的范围 |
| 圈子 C 的动态 | 作者在任一共同圈子勾了训练就显示 | 作者在 **C** 里勾了训练才显示（`feed.py` 已经按圈判断，只差按 C 过滤） |
| 圈子 C 的排行榜 | 所有共同圈子的人 | C 的成员；某人在 C 里没勾该榜需要的范围 → 「未共享」 |
| 点开 A 的只读页 | 并集 | 不变（并集），顶部标「通过 C1、C2 共享」 |
| 「全部」动态 | 混合 | 混合，帖子标圈子 |
| 帖子下的 ❤️ / 评论 | 写的人只要和**作者**有共同圈子就对所有能看帖的人显示 | 只显示**看的人**也和写的人有共同圈子的（在圈子 C 里只显示 C 的成员写的） |

最后一行是现在就有的隐私缺口：作者同时在家人圈和跑团里时，跑团成员的评论（名字 + 内容）家人也能看到，等于「朋友的朋友」互相可见，
和 `store.py` 里「friends of friends stay invisible」的原则不一致。建议在 P1 之前单独修（`feed.py` 的 `_WRITER_OK` 加上看的人这一侧）。

这样「每个圈子单独选范围」在圈子视图里就是字面意思；只读页仍是并集，界面上要写清楚来自哪些圈子（调研 §3 不借鉴第 4 条，Garmin 的教训）。

## 3. 圈子很多时的切换和管理

参考 Telegram（归档 + 置顶 + 文件夹）、Discord（按服务器静音）、Oura / WHOOP（数量上限）。每个成员对每个圈子有自己的偏好（只影响自己）：

| 操作 | 作用 | 对别人的影响 |
|---|---|---|
| 置顶（最多 3 个） | 出现在切换条最前面 | 无 |
| 最近 | 抽屉默认按「最近有动静」排序（新帖、新成员、新评论） | 无 |
| 静音 | 不发这个圈子的通知、红点；「全部」动态里不出现 | 无，**照常共享** |
| 归档 | 从切换条和「全部」里消失，抽屉底部「已归档」里还能找到 | 无，**照常共享**（归档时提示「你仍在共享 …，想停止请退出」） |
| 搜索 | 圈子 ≥ 6 个时抽屉顶部出现搜索框（按圈名、成员名 / 备注） | 无 |
| 退出 | 立即停止共享 | 对方立即看不到你 |

**被很多人拉进圈子**：入圈一直需要本人操作（输码或接受邀请），不会被直接「拉进去」。要优化的是邀请太多：

- 邀请收件箱合并在抽屉顶部（「3 个邀请」），每条写清「谁邀请 · 圈子多少人 · 加入后默认共享什么」，可以「全部忽略」；
- 个人设置「谁可以给我发圈子邀请」：和我有共同圈子的人（默认）/ 只有用过我推荐码的人 / 不接收（只能自己输码）；
- 每人上限保持 10 个圈子（Oura / WHOOP 同样是 10）；到上限时加入页直接说「先退出或归档一个」——注意归档不腾名额，名额只按「在里面」算。

## 4. 角色和权限

| 能做的事 | 圈主（1 人） | 管理员（≤ 5） | 成员 |
|---|---|---|---|
| 看成员、动态、排行榜 | ✓ | ✓ | ✓ |
| 看入圈记录（邀请链） | ✓ | ✓ | ✗（只看到「你邀请的人」） |
| 发邀请链接 / 码 | ✓ | ✓ | 按圈子设置「谁能邀请」 |
| 审批入圈申请 | ✓ | ✓ | ✗ |
| 移除成员 | ✓ | ✓（不能移除圈主和其他管理员） | ✗ |
| 改名、头像、默认共享范围、圈子设置 | ✓ | ✓（不能改「谁能邀请」和角色） | ✗ |
| 任命 / 撤销管理员、转让圈主、解散 | ✓ | ✗ | ✗ |

- 圈子设置「谁能邀请」：只有圈主和管理员 / 所有成员。
- 圈子设置「入圈审批」：关 / 成员邀请的要审批 / 全部要审批。审批时管理者看到：申请人名字、谁邀请的、通过哪个链接；**看不到申请人的任何健康数据**
  （人还没进圈，什么都没共享）。
- 推荐默认值见第 9 节（个人圈子 vs 俱乐部圈子不一样）。
- 圈主退出时仍转给最早的成员（现在的逻辑）；有管理员时优先转给最早的管理员。

## 5. 邀请链

### 5.1 记什么

每个 `circle_members` 行记：

| 字段 | 含义 |
|---|---|
| `invited_by` | 谁邀请的（用户；邀请人删号后 NULL） |
| `join_via` | `created`（建圈 / 个人圈子）、`invite_code`（圈子邀请码 / 链接）、`referral`（用某人的推荐码注册后接受的定向邀请）、`circle_code`（管理员发的圈子激活码）；以后加 `approved`（经审批）|
| `invite_id` / `circle_code_id` | 具体哪个邀请 / 哪个激活码 |
| `joined_at` | 已有 |
| `join_inferred` | 历史数据回填时只能推断出「大概是哪个链接」时为 true（邀请人仍准确） |

第一期（本 PR 之后马上做的小改动）已经加上这些字段，见第 8 节 P0。

### 5.2 谁能看

- 圈主、管理员：成员列表里每人一行小字「由 X 邀请 · 方式 · 日期」；邀请页里每条链接「通过它加入了 N 人」，点开列表。
- 成员：看不到别人的来源；只在「我邀请的人」里看到自己邀请进来的人（以后做）。
- 被邀请的人：接受前看到「X 邀请你」（现在已有）。

### 5.3 个人推荐码和圈子邀请码是两回事

| | 个人推荐码（`invite_codes` kind `referral`，「我」页） | 圈子邀请码 / 链接（`circle_invites`） | 圈子激活码（`circle_codes`，管理员发） |
|---|---|---|---|
| 属于 | 一个人 | 一个圈子（由某个人生成） | 一个圈子 |
| 作用 | 让朋友**注册账号**，记下推荐关系（`invite_redemptions.inviter_user_id`）和奖励 | 让人**加入这个圈子** | 注册账号 + 加入这个圈子（俱乐部推广） |
| 会不会带人进圈 | 只会给邀请人的**个人圈子**发一张定向邀请（对方要自己接受）；邀请人没有个人圈子就**不发任何圈子邀请** | 会，输码 / 点链接即加入（以后可加审批） | 会，同意书确认后入圈 |
| 入圈记录 | 「用了 X 的推荐码」 | 「由 X 邀请 · 邀请链接」 | 「圈子激活码『码』」 |

以前（到 #273 为止）推荐码在邀请人没有个人圈子时会退回到「他建的最早的一个圈子」，于是用某位圈主的个人推荐码注册的人被邀请进了他的俱乐部圈子——
这不符合「推荐码是个人的、不是圈子的」。#273 已改成只认个人圈子（`store.personal_circle`），迁移 745 停掉了还没被接受的这类邀请；已经接受入圈的保持不变。

### 5.4 转发怎么归属

- **圈子链接 / 码**：每条链接归**创建者**；谁转发都算在创建者头上（Telegram、Discord 同样只知道「用的是哪条链接」）。
  所以要让每个能邀请的人**用自己的链接**：成员点「邀请」生成的是自己名下的链接，不是共用的圈子码；链接可以命名（「群公告」「跑团微信群」），
  管理者按名字一眼看出来源。
- **个人推荐码**（`referral:u<id>`）：归推荐码的主人。主人把码发给 Y、Y 再转给 Z，系统只知道「Z 用了主人的码」——**转发路径无法可靠知道**，
  不做猜测（不在链接上加可伪造的 `?via=`）。界面写成「用了 X 的推荐码」，而不是「X 邀请」。
- **圈子激活码**：归圈子（管理员发的推广码），写成「圈子激活码『码』」，不算某个人邀请。
- 邀请人后来退出圈子或删号：记录保留，名字显示为「已退出的成员」/「已注销」。

## 6. 隐私：每圈单独设范围，默认最少

- 保留「每圈选范围」，加上第 2.1 节的按圈过滤，让它名副其实。
- **默认最少**：新加入一个圈子时默认只勾「评分 + 训练」（训练是动态需要的）；睡眠、饮食摘要改成「推荐，可勾」。家人用的个人圈子由本人自己加。
  具体默认值是第 9 节决定点 2。
- 入圈前（接受邀请 / 审批页）列出「加入后这个圈子的人能看到你的：…」（WHOOP 的做法），现在的加入页已有勾选，改成先给摘要。
- 圈子视图头部常驻一行「我在这里共享：评分 · 训练」，点开就能改。
- 管理员看到的入圈记录不含任何健康数据；邀请链不对成员公开，避免「谁和谁关系近」被推出来。
- 中国内地用户：不做陌生人发现、不做按手机号 / 通讯录匹配；邀请链只存用户 id，不存手机号或微信号。

## 7. 扩列和社群的平衡

- **扩列的唯一路径是熟人邀请链**：成员用自己的链接邀请 → （按圈子设置）圈主 / 管理员审批 → 入圈。不做公开圈子、搜索、推荐陌生人。
- **社群氛围靠三件事**：圈子人数上限（默认 30，俱乐部圈子由管理员调）、审批开关、静音 / 归档让人不必退出也能降噪。
- **俱乐部圈子**（管理员用激活码建的大圈子）：默认「只有圈主和管理员能邀请」+「成员邀请要审批」；默认共享更少（只评分 + 训练）；
  成员卡片只显示你和他另外还有共同圈子的人的完整卡片，其他人只显示头像 + 名字（参考 Strava 大俱乐部只列你关注的人）。
- 「全部」视图里同一个人只出现一次，避免「好友数」虚高的感觉。

- 同意书：P1、P2 不改变谁能看到什么，不用改；P3「成员可以邀请别人进圈」让圈子成员可能变成「朋友的朋友」，同意书「圈子共享」一节要不要补一句由负责人定（第 9 节 5）。
- 管家工具 `get_friends_overview` 在 P1 加 `circle` 参数，默认仍返回汇总。

## 9. 要负责人决定的点

| # | 问题 | 选项 | 推荐 |
|---|---|---|---|
| 1 | 「全部」视图要不要排行榜 | a 不要（只能按圈看）/ b 要，跨圈混排 | **a**：不同圈子的人互不认识，混排没意义 |
| 2 | 新入圈默认共享范围 | a 保持现在 4 项（评分、睡眠、训练、饮食摘要）/ b 只「评分 + 训练」/ c 个人圈子 4 项、俱乐部圈子 2 项 | **c**：家人小圈子保持方便，大圈子默认最少 |
